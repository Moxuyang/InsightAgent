# 智能体与业务页面联动

本轮围绕“采集 → 监测 → 解读 → 协作”连接现有功能。首页仍为工作台。

## 已接通的流程

- **个人 AI 问答**：通过 LangGraph 查询新闻、执行只读业务查询、准备证据并流式生成回答。日期范围和命中总数由数据库确定，来源随回答保存。
- **舆情洞察**：先按采集日期范围和个人关键词库匹配新闻，展示关注词、风险词、问题词命中统计；点击 AI 解读可将该阶段的问题带入问答。进入问答后仍需用户点击发送。
- **数字大屏**：提供 AI 解读入口，将系统总览、今日采集和来源分布的解读问题带入问答。统计由数据库提供，模型负责解释。
- **数字员工**：群聊中的新闻问题复用同一套证据检索与流式回答流程，同时保留员工角色、技能说明、群聊上下文、来源和实际 Token 用量。
- **阅读体验**：群聊数字员工的流式回答和历史回答也使用安全 Markdown 渲染。

## 数据边界

个人问答的用户身份由服务端登录态提供。个人关键词库只用于该用户的私有问答，群聊不会读取个人词库。群聊消息读取、发送及数字员工调用校验成员资格，员工必须已加入该群组。

词库中的“风险词”“问题词”是用户配置的分类；命中仅表示需要核查，不能作为已确认风险或事实结论。没有金额识别功能。

当前业务工具只读取数据。AI 解读不会自动采集、修改权限、删除文件或发送通知。正常发送 AI 问题时，检索片段会使用已经配置的模型服务进行回答；本轮验证使用本地测试与模拟模型，没有发送实际新闻进行外部模型测试。

## 后续适合接入的方向

1. 文件空间：CSV/TXT/Markdown已支持按用户权限读取并接入问答；后续可扩展PDF/Word/Excel解析、引用定位与语义检索。
2. 采集任务：将任务状态、失败原因和重试入口接入智能体，让用户能追踪采集是否完成。
3. 数字员工技能：从现有固定接口调用进一步发展为按任务选择工具，并明确每种工具的读写范围。
4. 设备数据：当前新闻系统不能等同于已接入真实 AIoT 设备；需接入实际设备接口、时间序列和告警规则后再增加设备解读。

## 验证

相关自动化覆盖新闻时间范围检索、个人词库隔离、监测证据替换、角色提示约束、群组访问控制、数字员工流式引用与 Token 保存，以及页面和静态资源加载。模型生成使用模拟响应，未验证外部模型的实际回答质量。
