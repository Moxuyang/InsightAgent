# 附件内容分析

完整的“采集新闻 → 监测 → 上传 CSV → AI 分析”实例、实际问答及运行截图直接保存在 [README](../README.md) 中。可上传样例为 [collected-news.csv](examples/collected-news.csv)，内容来自本次公开新闻采集的标题、来源、链接及明确规则的派生列。

## 用户操作

1. 在 AI 问数中新建会话，使用附件按钮上传 CSV、TXT 或 Markdown。
2. 等待文件标签显示上传成功，输入问题并发送。只上传而未发送，不会调用模型。
3. 后端校验文件归属并读取实际内容，CSV 数值列先计算统计，再与问题一起作为证据交给已配置模型。
4. 在同一会话继续追问时，后端重新加载已绑定附件，无需再次上传。刷新或重开历史会话后绑定仍保留。
5. 新主题应新建会话；新会话不会自动使用上一会话的附件。文件空间用于核对存储记录，其文件不会自动全部进入模型上下文。

## 范围与限制

| 项目 | 限制 |
| --- | --- |
| 分析格式 | CSV、TXT、MD；其他格式仍可上传存储，但不解析 |
| 会话附件 | 最多3个 |
| 单文件分析大小 | 2MB以内（存储上传上限与分析上限不同） |
| 文本长度 | TXT/MD不超过40000字符 |
| CSV结构 | 首行表头，非空且不重复，最多50列；数据行列数一致 |
| CSV规模 | 最多10000个非空数据行 |
| 编码 | 优先UTF-8/BOM，兼容GB18030 |
| 数值统计 | 对所有非空单元格均为有限数值的列，计算全行数量、缺失、总和、最小、最大、平均 |
| 明细证据 | 最多前100行；过长时降为前10行，保留明确样本数量；仍过长则要求精简 |

数值计算使用 Decimal。混合文本列不会被强制转换为数值；单位、千位逗号、百分号等带格式字符串不自动猜测转换。超过限制或格式不符合要求时会拒绝分析，不能将不完整结果当作全量统计。

附件及CSV单元格都作为不可信参考数据，不执行其中的代码或指令。文件证据与新闻证据分开处理；当前会话含附件时优先分析附件，不把同名新闻替代附件内容。文件行号与来源引用编号分别表示，CSV行号应写作“第N行”。

## 实现与权限

- `app/services/file_context.py`：解析、大小限制、统计、文件归属和路径检查。
- `POST /api/news_qa`：表单新增 `file_ids`，值为JSON数组字符串，例如 `[12]`；仍使用登录态和XSRF保护。
- `chat_session_files`：记录当前会话与已选文件的关联，首次使用问答时按需创建。
- 附件以服务端记录的路径读取，仅允许位于项目 uploads 目录下的真实文件；前端不能提供任意本地路径。
- 读取附件和历史绑定时校验用户及会话归属。没有权限或已删除的记录不会被静默当作有效证据。

CSV解析是只读操作，不会导入业务指标表，也不执行模型生成的脚本。真正发送问题时，附件证据会提交到已配置的大模型服务，使用者应确认内容适合该服务处理。

## 验证

```bash
python -m unittest discover -s tests -p test_file_context.py -v
```

测试覆盖真实CSV统计、跨用户文件与会话隔离、后续问题保留附件、目录越界、重复表头、错列和不支持格式。本次还通过真实页面上传公开新闻CSV，用实际模型回答核对了10行、215字、1/2/2条命中与正文记录，以及10%/20%/20%的比例。
