# 新闻资料问答

智能问答主页现在调用 `POST /api/news_qa`。模型引擎的测试接口仍用于测试连接。

## 执行流程

LangGraph `StateGraph` 编排四个节点：

1. `retrieve_news`：从 `spy_data` 检索标题、关键词、摘要，以及 `deep_collect_results` 中成功提取的正文。同一新闻采用最新成功正文，最多选取 6 条证据。提供全库新闻条数、已提取正文条数及来源统计。
2. `business_tools`：按问题执行只读业务工具，例如读取当前用户的个人关键词命中统计并替换为对应新闻证据；群聊不读取个人词库。
3. `prepare_context`：组合系统约束、当前会话最近 8 条消息、检索证据、业务结果及问题；数字员工还加入角色说明。来源采用 `[1]` 等编号，采集时间与事件时间明确区分。
4. `generate_answer`：使用服务端提供的模型配置，通过兼容 OpenAI 的流式接口调用模型。个人问答使用默认模型，数字员工使用绑定模型。模型配置不进入图状态，也不发往浏览器。

这是基于数据库关键词检索的 RAG，支持中文短语与二字片段匹配；没有向量数据库或 Embedding 依赖。候选记录上限为 120 条，普通主题按标题和正文匹配排序，时间查询优先按采集时间排序。

“今天”“昨天”、明确日期、最近 N 天和本周均在 SQL 中执行半开时间范围过滤。“最新”限定为最近一个有匹配采集记录的北京时间日期，不跨日期补足展示数量。“最近/近期”默认查询最近 7 个北京时间自然日。默认最多展示 6 条，可以指定至多 10 条；命中总数与展示条数分别给出。

SQLite 的时间按 UTC 解释，MySQL 则读取会话相对 UTC 的偏移；查询边界换算到数据库时区，输出统一使用北京时间。模型系统消息每轮注入服务器当前时间、实际查询时间范围和命中数，以覆盖历史回答中错误的日期判断。时间查询无匹配时不回退到旧新闻。

问答页通过本地 Marked 和 DOMPurify 渲染安全的 Markdown，支持流式回答和历史回答中的标题、加粗、列表、引用、代码块、表格及链接。禁用模型生成的脚本、事件属性、图片等内容。库版本见 `app/static/vendor/markdown-versions.json`。

原来的整库上下文拼接不再由问答浏览器请求。模型只能读取固定的检索和统计结果，不生成或执行任意 SQL。附件分支支持CSV、TXT、Markdown有界读取、数值统计与会话绑定，详见 [附件分析规则](file-analysis.md)；其他文件类型目前仅存储。

## 流式事件

接口沿用 SSE 的 `data: JSON` 格式，依次发送：

- `session`：服务器确认的会话 ID。
- `status`：检索和生成阶段的用户提示。
- `sources`：新闻编号、标题、来源、链接、采集时间、正文/摘要标记。
- `content`：回答文本片段。
- `done`：保存完成及 token 数量；随后发送 `[DONE]`。
- 失败时发送 `error`，不把不完整回答作为成功记录保存。

消息、问答记录、token 统计由后端统一写入；客户端不再重复保存。会话按当前登录用户校验。引用来源随回答保存到历史和导出数据中。页面将问题、模型输出和来源标题作为文本渲染，仅允许 HTTP(S) 来源链接。

## 安装与验证

Python 3.11+，安装 `requirements.txt` 或 `requirements-lock.txt` 后重启服务。

```text
python -m unittest discover -s tests -p test_news_qa.py -v
node tests/test_news_qa_stream.cjs
```

测试使用临时数据库和模拟模型，验证真实图执行、正文优先、来源去重、无匹配、会话归属、保存回滚及流式帧分片，不消耗实际模型额度。

LangGraph 自定义流式事件的实现参考：[官方 Streaming 文档](https://docs.langchain.com/oss/python/langgraph/streaming)。
