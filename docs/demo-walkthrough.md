## 天气数字员工的完整配置流程

### 第一步：选择公开天气接口

采用 [Open-Meteo Weather Forecast API](https://open-meteo.com/en/docs)。本例查询成都固定位置，使用以下请求：

```http
GET https://api.open-meteo.com/v1/forecast?latitude=30.67&longitude=104.06&current=temperature_2m,relative_humidity_2m,apparent_temperature,precipitation,wind_speed_10m&timezone=Asia%2FShanghai&forecast_days=1
```

| 参数 | 本例设置 | 用途 |
| --- | --- | --- |
| latitude / longitude | 30.67 / 104.06 | 成都固定查询位置 |
| current | 五项天气变量 | 获取气温、湿度、体感、降水及风速 |
| timezone | Asia/Shanghai | 以北京时间标记数据时间 |
| forecast_days | 1 | 限定请求预报范围；员工展示 current 数据 |

此配置不需要填写 API Key。免费接口适用条件、限流和商业使用要求请以服务方说明为准。返回坐标可能是服务匹配到的模型网格坐标，并不一定与请求坐标逐位相同。

### 第二步：在技能管理创建 API 技能

进入“技能管理”，点击“创建技能”。按下表填写并保存：

| 界面字段 | 设置 |
| --- | --- |
| 技能名称 | 成都天气查询 · Open-Meteo |
| 技能类型 | function_call（外部 API 调用） |
| 分类 | tool |
| 功能描述 | 查询成都固定位置当前天气；不自动切换城市或日期 |
| API 地址 | 上述完整请求地址 |
| 请求方法 | GET |
| 请求头 | `{}` |
| 请求体模板 | 留空 |
| 响应字段 | 留空，以便保留 current、units、time 与坐标信息 |
| 启用状态 | 启用 |



保持“响应字段”为空时，系统会将识别到的天气结构整理成中文指标表格，包含原始单位和数据时间。若仅提取 `current.temperature_2m`，则会丢失单位与来源上下文，不适合此演示。

### 第三步：创建并绑定数字员工

进入“数字员工”，添加员工并填写：

- 名称：**成都天气助手**。
- 角色：查询成都固定坐标当前天气，直接返回天气接口数据。
- 模型：可不绑定。本例为纯 API 工具员工，不调用大模型。
- 技能：勾选 **成都天气查询 · Open-Meteo**。
- 状态：启用。

保存后重新打开配置，确认技能仍然处于勾选状态。


### 第四步：创建群聊并邀请员工

1. 进入“协作消息”，点击“发起群聊”。
2. 输入群名称，例如 **天气查询演示**，填写用途说明后创建。
3. 打开该群，点击“邀请”，切换到数字员工选项，勾选 **成都天气助手** 并确认。
4. 点击“查看群成员”，确认员工已出现在列表中。

本次群聊仅包含演示账号和天气员工，没有向其他真人用户发送消息。


### 第五步：在群聊中 @ 员工

输入以下消息；使用 @ 候选列表选择员工后，再补充任务内容：

> @成都天气助手 请查询成都现在的天气，列出气温、体感温度、湿度、风速和降水量。

点击发送后，界面先显示 API 调用状态，再流式显示天气结果，完成后保存到群聊历史。员工名称后保留空格，方便区分提及对象与问题。


### 第六步：检查实际返回与持久化

本次接口数据时间为 **2026-10-22T13:00，Asia/Shanghai**：

| 指标 | 实际返回值 |
| --- | --- |
| 气温 | 18.9 °C |
| 体感温度 | 19.5 °C |
| 相对湿度 | 74% |
| 风速 | 4.8 km/h |
| 降水量 | 0.1 mm |


关闭并重新打开群聊后，天气回复仍可从历史消息中读取。表格下方保留数据来源，说明这是天气模型数据，并非现场设备传感器读数。

### 适用范围与复现

本例展示的是“外部 API → 技能 → 数字员工 → 群聊消息”的真实执行链路。对同一员工追问“上海天气”不会自动切换城市；若要支持多城市，需要增加城市解析、地理编码和对应工具参数。本例也不提供明天天气或历史天气查询，不能将 current 返回当成未来预测回答。

在项目已经完成首次启动、且指定账号存在后，可使用仓库脚本快速创建相同配置：

```bash
python scripts/setup_weather_demo.py --username admin
```

该脚本创建技能、员工和指定账号拥有的群组，并把员工加入群组；不会创建真人消息、不会调用天气接口、不会调用模型，也不会写入模型密钥。同名配置再次运行时复用，不覆盖原配置。

当前工作区的默认管理员账号下已创建同名天气技能、员工与群组，进入协作消息即可自行发起查询。用于公开截图的对话则保存在独立演示环境中。
